## 1. الأخطاء الحرجة التي كانت تُعطّل الميزة بالكامل

### 🔴 1. انهيار TDZ — كل طلب يفشل بـ 500
**الملف:** `supabase/functions/vin-analyze/index.ts`
سطور التشخيص كانت تقرأ `step` و `rawVin` **قبل** تعريفهما بـ `const` (Temporal Dead Zone) → كل طلب يرمي `ReferenceError` → يُلتقط في الـ catch العام → **500 لجميع النداءات**. الميزة لم تعمل ولو مرة واحدة منذ إضافة سطور التشخيص.
**الإصلاح:** حذف كتلة التشخيص بالكامل.

### 🔴 2. تسريب جزئي لرمز JWT في سجلات Supabase
`authHeader.substring(0, 30)` كان يُسجَّل مع كل طلب — أول 30 حرفاً من JWT تكفي لكشف header + بداية payload.
**الإصلاح:** حُذف مع كتلة التشخيص. تبقّى فقط تسجيل رسالة الخطأ عند فشل `getUser()`.

### 🔴 3. عدم تطابق توقيع RPC — صفر نتائج مخزون صامتة
الدالة الطرفية تستدعي `search_by_oem` بـ `p_limit: 20` بينما الـ RPC الأصلي يقبل `(p_company_id, p_search_term)` فقط → PostgREST يرد **PGRST202** → الخطأ كان يُبتلع (`const { data } = ...` دون فحص `error`) → صفر مطابقات دائماً.
**الإصلاح:**
- Migration جديد `20260812000001_search_by_oem_limit.sql`: إعادة إنشاء الدالة بمعامل `p_limit INT DEFAULT 20` (مثبَّت بين 1 و100) — النداءات القديمة بمعاملين تظل تعمل بفضل الـ DEFAULT.
- الدالة الطرفية الآن تسجّل `rpcErr` بدل ابتلاعه.

### 🔴 4. عدم تطابق أسماء الحقول — الكمية دائماً 0 والسعر null
الـ RPC يُرجع `product_sku` / `stock_quantity` / `sale_price` بينما الكود كان يقرأ `sku` / `quantity` / `price`.
**الإصلاح:** تصحيح التخطيط مع دعم الاسمين (دفاعياً) + إزالة التكرار بـ `productId` (أرقام OEM متعددة قد تطابق نفس المنتج).

### 🔴 5. جدول `vehicle_core_parts` فارغ بلا أي مسار تعبئة
لا seed، لا واجهة إدخال، لا استيراد، لا توليد → تبويبات القطع/المخزون/الطلب فارغة دائماً — **السبب الجذري لإحساس "الميزة الوهمية"**.
**الإصلاح:** مسار احتياطي بالذكاء الاصطناعي `generateCorePartsWithAI()` في الدالة الطرفية:
- عندما تُفكّك مركبة ولا توجد قطع لها، يُسأل نموذج LLM (OpenRouter `gemini-2.5-flash` أو DeepSeek — نفس أسرار `ai-proxy` المشتركة) عن أكثر 15 قطعة استهلاكية للمركبة في السوق الخليجي.
- تُدرج القطع موسومة بوضوح: `fitment_status = INFERRED` و `evidence_source = AI_GENERATED_UNVERIFIED` و `evidence = "AI-suggested part — pending human verification."` — **لا تُقدَّم كحقائق**.
- البرومبت يمنع اختلاق أرقام OEM صراحةً ("NEVER invent plausible-looking numbers").
- تعمل في المسارات الثلاثة: خطوة `parts`، والوضع الكامل (المخزَّن مؤقتاً والجديد).
- لا ترمي أخطاء أبداً — عند أي فشل تعود 0 ويكمل التدفق كالسابق.

## 2. إصلاحات الموثوقية والأداء (الدالة الطرفية)

| # | الإصلاح | التفاصيل |
|---|---------|----------|
| 6 | **مهلة NHTSA** | `AbortSignal.timeout(10_000)` — طلب معلّق لم يعد يجمّد الدالة حتى حد الـ wall-clock؛ حالة جديدة `DECODER_TIMEOUT` |
| 7 | **Cache-before-decode** | `getCachedVehicle()` يفحص `vehicle_knowledge_base` أولاً — الـ VINs المعروفة تتخطى NHTSA تماماً (`provider: "knowledge_base_cache"`) في خطوة `validate-decode` والوضع الكامل |
| 8 | **فشل سريع عند غياب الشركة** | `company_id = null` كان يمرر صامتاً → صفر نتائج RLS. الآن يرد `400 / NO_COMPANY` بوضوح |
| 9 | **إظهار الأدلة لكل الحالات** | `evidence` كانت تُصفَّر لغير VERIFIED رغم أن الدرج يعرضها للجميع — الآن تمر دائماً |
| 10 | **فهرس مفقود** | `CREATE INDEX idx_vehicle_core_parts_vehicle ON vehicle_core_parts(vehicle_id)` (في نفس الـ migration) |

## 4. خطوات النشر المطلوبة (يدوياً — تحتاج صلاحيات)

```powershell
cd alzhraERP
npx supabase link --project-ref zzthamxjxnxzzpswllid
npx supabase db push                                  # يطبّق 20260812000001_search_by_oem_limit.sql
npx supabase functions deploy vin-analyze
```

> **ملاحظة:** توليد القطع بالـ AI يستخدم `OPENROUTER_API_KEY` أو `DEEPSEEK_API_KEY` — نفس الأسرار المشتركة الموجودة أصلاً لـ `ai-proxy`، فلا حاجة لإعداد جديد غالباً. تحقق: `npx supabase secrets list`.

### اختبار يدوي بعد النشر
1. VIN أمريكي معروف: `1HGCV1F34LA012345` (Honda Accord 2020) — يجب أن يُفكّك وتظهر قطع AI موسومة INFERRED.
2. أعد إدخال نفس الـ VIN — يجب أن يرد فوراً من الكاش (تحقق من `provider: knowledge_base_cache` في استجابة الشبكة).
3. أضف منتجاً في المخزون `part_number` يطابق رقم OEM مولّد — يجب أن يظهر في تبويب المخزون **بكمية وسعر صحيحين** (كانا 0/null قبل الإصلاح).
4. حلّل VIN ثانٍ مختلف — رؤى AI يجب أن تُعاد (كانت تبقى قديمة).
5. افتح درج أي قطعة → زر "تحليل القطعة" يجب أن يعرض شرح AI.
