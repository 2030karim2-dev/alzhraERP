## المرحلة 1: تنظيف المسارات والروابط (أسبوع 1)

### الهدف
إزالة التكرار في المسارات، إصلاح القوائم الجانبية، وتوحيد نقاط الدخول.

### الخطوات العملية
1. **توحيد مسارات الأطراف** (`/clients`, `/suppliers`, `/parties/*`)
   - تعديل `src/core/routes/paths.ts`: الاحتفاظ بـ `PARTIES: '/parties'` فقط.
   - تعديل `src/app/routes.tsx`: حذف المسارات المكررة.
   - تعديل `src/features/parties/PartiesPage.tsx`: إضافة تبويبات داخلية (عملاء / موردين) بدلاً من توجيه المسار.
   - تحديث جميع الروابط الداخلية (`Link`, `navigate`) التي تشير إلى `/clients` أو `/suppliers`.

2. **إصلاح القائمة الجانبية** (`src/core/constants.ts`)
   - تقليل عدد العناصر من 14 إلى 9:
     - **تحافظ:** نظرة عامة، الفواتير، المنتجات، المبيعات، المشتريات، المصاريف، المحاسبة، الإعدادات.
     - **تدمج:** السندات ← المحاسبة.
     - **تخفي:** الذكاء الاصطناعي ← قائمة تحتاج تفعيل (Feature Flag).
     - **تزيل أو تخفي:** بحث المركبات ← تبويب داخل المخزون.
   - تحديث `src/ui/layout/sidebar/SidebarNav.tsx` ليعكس التغييرات.

3. **تنظيف مسارات المصادقة**
   - حذف `/login` و `/register` من `src/app/routes.tsx` (موجهة تلقائياً إلى `/welcome`).
   - التأكد من عدم وجود روابط داخلية تشير إليها.

### الموارد المطلوبة
- مطور أمامي (1)
- Reach من الاختبارات (إن وجدت)

### المسؤوليات
- **مطور المشروع الرئيسي:** تنفيذ التعديلات.
- **مراجع:** مراجعة الاختبارات والروابط المكسورة.

### معايير النجاح
- عدد المسارات النشطة انخفض من 25+ إلى 18.
- لا توجد روابط مكسورة في القائمة الجانبية.
- جميع أزرار التنقل تعمل بشكل صحيح.

## المرحلة 9: اختبار Integration وRelease (أسبوع 6)

### الهدف
التأكد من أن جميع التغييرات تعمل بشكل متكامل.

### الخطوات العملية
1. **تشغيل الاختبارات**
   - `npm run lint`
   - `npm run typecheck` (إن وجد)
   - `npm run build`
   - تشغيل الاختبارات اليدوية على:
     - سطح المكتب (1920px, 1440px, 1024px)
     - الجوال (iPhone, Android)

2. **اختبار التنقل**
   - التأكد من أن جميع الروابط تعمل.
   - التأكد من عدم وجود صفحات 404 غير مقصودة.

3. **اختبار الأداء**
   - قياس سرعة تحميل الصفحة الرئيسية قبل وبعد.
   - قياس حجم الحزمة (`npm run build` && `du -sh dist`).

4. **إعداد ميزات الذكاء الاصطناعي المستقبلية**
   - إنشاء Feature Flags (`VITE_ENABLE_AI`) لتفعيل/تعطيل ميزات الذكاء الاصطناعي القادمة.
   - توثيد بنية AI الحالية (الموفّر، المحادثة، intent) للاستخدام المستقبلي.

### الموارد المطلوبة
- مطور أمامي (1)
- مختبر (1) — إن أمكن

### المسؤوليات
- **مطور المشروع الرئيسي:** التنفيذ.
- **مختبر:** الاختبار اليدوي.

### معايير النجاح
- لا توجد أخطاء في البناء.
- جميع الاختبارات تمر.
- سرعة تحميل الصفحة الرئيسية تحسنت بنسبة ≥ 30%.
- حجم الحزمة الإجمالية انخفض بنسبة ≥ 15%.
