# ADR-015: Super Admin Platform Operations — Fail-Open Guards, Trial Rules & Full Export

- **التاريخ:** 2026-09-04
- **الحالة:** مقبول (Accepted)
- **النطاق:** قسم Super Admin (مركز تحكم المنصة) — `features/admin` وترحيلات `20260903000002..20260904000009`

## السياق (Context)

راجَعنا قسم السوبر أدمن بدقة (واجهة + RPCs + RLS) وظهرت أسئلة معمارية تتطلب توثيقاً صريحاً:

1. حُرّاس الصيانة والميزات (`MaintenanceGuard` / `usePlatformFeatureFlags`) تعمل **Fail-Open**: أي فشل في قراءة
   `system_platform_configs` يعيد القيم الافتراضية (`maintenance_mode.enabled=false` وكل الميزات `true`).
2. دالة `extend_company_trial` كانت تعيد `is_active=true` تلقائياً لأي شركة، ما يجعلها أداة **إعادة تفعيل** غير مقصودة.
3. `toggle_company_status` كان يستبدل حالة `past_due`/`cancelled` بـ `suspended` عند التعليق، فيفقد الحالة الأصلية
   وتعود إعادة التفعيل بـ `active` مجاناً.
4. تصدير CSV كان يصدّر **صفحة العرض فقط** (25 صفاً) رغم توفر عدّادات كاملة.
5. لا bootstrap ذاتي للسوبر أدمن (قرار تشغيلي يدوي عبر `seed_super_admins.sql`).

## القرارات (Decisions)

### 1. حُرّاس الصيانة/الميزات تبقى Fail-Open — موثقة

- **القرار:** لا نغيّر السلوك الحالي؛ أي تعذّر في قراءة إعدادات المنصة يُبقي النظام متاحاً (لا حجب خاطئ).
- **المبرر:** أولوية **التوفر** أثناء أعطال قاعدة البيانات؛ الخطأ العكسي (حجب الجميع بسبب قراءة فاشلة) أسوأ أثراً.
- **الحدود:** Fail-open ينطبق على _بوابات الواجهة فقط_. الحماية الفعلية للبيانات تبقى Fail-Closed على مستوى
  RLS و`fn_assert_company_access`/`get_auth_companies` (السوبر أدمن لا يتجاوز `is_active=false`).
- **تحسين مستقبلي:** بوابة تنفيذ على مستوى الخادم (Edge/Postgres) لوضع الصيانة الحقيقي إن لزم حجب كتابي.

### 2. تمديد التجربة ليس أداة إعادة تفعيل (ترحيل 20260904000009)

- `extend_company_trial` يرفض الآن المنشآت غير النشطة/الموقوفة/الملغاة برسالة عربية واضحة.
- إعادة التفعيل مسار واحد موحّد: `toggle_company_status` من لوحة الإدارة.

### 3. التعليق يحفظ الحالة الأصلية (ترحيل 20260904000009)

- عند التعليق تبقى `past_due`/`cancelled` كما هي (`is_active=false` هو الحاجز)، فتعيد إعادة التفعيل الحالة
  الصحيحة بدل `active` مجانية. منطق الواجهة (`deriveStatusAfterToggle`/`companyStatusLabel`) متزامن مع الخادم.

### 4. البذر التشغيلي للسوبر أدمن (لا تغيير)

- لا توجد آلية self-bootstrap داخل التطبيق؛ البذر عبر `supabase/scripts/seed_super_admins.sql` بصلاحية postgres.
- **المخاطرة المقبولة:** إن فُقد آخر سوبر أدمن يلزم تدخل DBA — مقبول لأن السكربت Idempotent وموثق في README.

### 5. التصدير الكامل CSV عبر تجزئة الخادم

- دوال `exportAll*` في `adminService` تجلب كل النتائج المطابقة للفلاتر الحالية عبر صفحات متسلسلة
  (500 للقوائم، 200 لسجلات الأمان/CSP لاحترام حد الخادم) بدل تصدير صفحة العرض.

## العواقب (Consequences)

- الواجهة والخادم متطابقان دلالياً بعد تطبيق `20260904000009` (يجب تطبيق الترحيل قبل/مع نشر الواجهة).
- المصطلحات موحّدة في واجهة الإدارة: حالة التعليق = "موقوفة"، والإجراء = "تعليق/إعادة تفعيل".
- تصدير كميات كبيرة قد يستغرق وقتاً أطول — الزر يعرض حالة "جاري التصدير" ويمنع التكرار.
- Fail-open للحُرّاس موثق هنا كقرار مقصود وليس سهواً.
