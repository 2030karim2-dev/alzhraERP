# Security Hardening — Evidence & Vulnerability Matrix

**Audit date:** 2026-08-26
**Auditor:** Plan-driven security sweep (G1–G10 + Phase 14/18/20/21/22/23 + CI integration)
**Scope:** Frontend (Supabase client, auth store, CSP, source maps, dev guards, input validation), Edge Functions (zatca, vin-decode, part-search), Database (RLS sweep, function grants, storage MIME + bucket policies, chat sanitization, idempotency index, audit logging, input validation triggers, atomic rate limiting), Dependencies (`npm audit`), CI integration (canary SQL, GitHub Actions workflow, SECURITY.md).

## Executive Summary

| Severity  | Found  | Fixed  | Accepted |
| --------- | ------ | ------ | -------- |
| CRITICAL  | 1      | 1      | 0        |
| HIGH      | 4      | 4      | 0        |
| MEDIUM    | 11     | 9      | 2        |
| LOW       | 2      | 2      | 0        |
| INFO      | 1      | 1      | 0        |
| **TOTAL** | **19** | **17** | **2**    |

**Key wins (this audit):**

- Discovered and fixed a CRITICAL cross-tenant write vulnerability in 39 `api_v1_*` functions (R-26).
- Discovered and fixed a HIGH cross-tenant file-read in `invoices` and `company-assets` storage buckets (R-27).
- Fixed ZATCA XML injection (R-09) and Authorization-header leak in console (R-11).
- Hardened CSP, idempotency, rate limiting, audit logging, and input validation.
- Established a 6-step CI canary (`.github/workflows/security-canary.yml`) that runs weekly and on every PR.
